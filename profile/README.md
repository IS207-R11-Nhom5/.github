- **Rõ người, rõ việc:** mỗi công việc cần có người phụ trách, đầu ra, hạn hoàn thành và người rà soát.

- **Cập nhật tiến độ:** khi gặp vướng mắc hoặc có nguy cơ trễ, báo sớm để điều chỉnh hoặc hỗ trợ.

## Quy trình thực hiện công việc

Quy ước dưới đây hướng dẫn các công việc tiếp theo; lịch họp, hạn và người review được thống nhất theo từng nhiệm vụ.

### Đối với công việc lập trình

1. Thống nhất yêu cầu, người thực hiện, người review và tiêu chí hoàn thành. Ghi vấn đề cần xử lý tại Issues hoặc tài liệu công việc của nhóm.
2. Cập nhật mã nguồn từ `main`, tạo nhánh theo nội dung: `feat/<noi-dung>`, `fix/<noi-dung>` hoặc `docs/<noi-dung>`.
3. Thực hiện thay đổi trong nhánh, tự kiểm tra phần mình phụ trách và các luồng bị ảnh hưởng.
4. Đẩy nhánh lên repository gốc, tạo Pull Request mô tả thay đổi và kết quả kiểm tra; gửi thành viên phụ trách tích hợp rà soát.
5. Nếu có lỗi, xung đột hoặc CI chưa đạt, sửa trong cùng nhánh và kiểm tra lại.
6. Gộp thay đổi sau review, kiểm tra bản triển khai và cập nhật trạng thái công việc cùng minh chứng.

```sh
# Tạo nhánh cho công việc mới
git switch main
git pull --ff-only origin main
git switch -c feat/ten-cong-viec

# Lưu và đẩy nhánh để mở Pull Request
git add <cac-file-da-kiem-tra>
git commit -m "feat: mo ta thay doi"
git push -u origin feat/ten-cong-viec
```

### Đối với thiết kế, nội dung và tài liệu

1. Chốt yêu cầu và nơi lưu đầu ra: Figma, Notion hoặc repository tài liệu.
2. Gửi đường dẫn hoặc bản nháp cho người phụ trách rà soát, ghi rõ phần cần phản hồi.
3. Sửa theo phản hồi, cập nhật link bản cuối và lưu minh chứng. Nội dung tài liệu cần khớp với sản phẩm đang chạy.

### Trạng thái công việc

| Trạng thái | Ý nghĩa |
| --- | --- |
| Chưa bắt đầu | Đã ghi nhận yêu cầu và người phụ trách |
| Đang làm | Đang triển khai hoặc sửa theo phản hồi |
| Chờ kiểm tra | Đã có đầu ra, đang chờ review hoặc kiểm thử |
| Hoàn thành | Đã rà soát, có minh chứng và được xác nhận trong nhóm |

## Quy trình CI

Repository uitplans có workflow GitHub Actions kiểm tra khi push `main` và khi mở/cập nhật Pull Request:

| Bước | Nội dung |
| --- | --- |
| `npm ci` | Cài dependency theo lockfile |
| `npm run check` | Chạy kiểm tra tĩnh đã cấu hình trong dự án |
| `npm run check:features` | Kiểm tra các quy tắc và chức năng được tự động hóa |
| `npm run build` | Kiểm tra khả năng tạo bản production |

[Xem workflow uitplans](https://github.com/haiphamt/uitplans/blob/main/.github/workflows/check.yml). Ngoài CI, cần kiểm tra luồng liên quan trên desktop/mobile và bản online. Không đưa `.env`, OAuth secret, token hoặc mật khẩu vào mã nguồn.

Với TravelGo, lệnh kiểm tra và quy trình frontend/API/database được cập nhật trong README theo phần thực sự triển khai.

## Kiểm tra và triển khai

- **uitplans:** build và triển khai bản frontend lên Netlify. Sau triển khai, kiểm tra Guest, Google callback, lưu/tải kế hoạch và các luồng vừa thay đổi. Chỉ xem công việc đã hoàn thành khi bản online được kiểm tra.
- **TravelGo:** đang phát triển; đối chiếu tiến độ, môi trường và cách chạy tại repository gốc. Bản thiết kế không được dùng để khẳng định backend hoặc toàn bộ nghiệp vụ đã hoạt động.
- **Khi có lỗi:** ghi cách tái hiện, người phụ trách, ảnh/log phù hợp và kết quả kiểm tra lại sau khi sửa.
